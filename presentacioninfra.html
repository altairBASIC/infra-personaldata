7 Decisiones de Diseno
Patron registry @regla
Agregar reglas de calidad no modifica codigo existente. Cerrado a modificacion, abierto a extension.
uuid5 para signal_id
Idempotencia: mismo correo produce el mismo ID. Permite re-ejecuciones sin duplicados.
Polars + Parquet + DuckDB
Columnar, eficiente en memoria. DuckDB lee Parquet sin servidor. Particionamiento por anio/mes.
Chunking con overlap
512 tokens, 50 de solapamiento. No se pierde contexto en los limites de cada chunk.
Modelo horneado en build
Se descarga durante docker build y queda en la imagen. Runtime 100% offline.
lru_cache en embeddings
El modelo se carga una vez por proceso. /search baja de ~4.9s a ~15ms tras la primera carga.
8 Alternativas Enterprise: Soberanía de Datos

Nuestro proyecto demuestra la arquitectura a escala académica. A nivel enterprise, estas son las opciones reales, ordenadas por nivel de soberanía sobre los datos.

TIER 1 Red Hat OpenShift
Soberanía total + integración completa
▶ OpenShift AI con certified operators para ML/LLM
▶ LlamaStack integrado para agentes locales
▶ Red Hat Trusted Software Supply Chain
▶ On-premise o bare metal, datos nunca salen
TIER 2 SUSE Rancher + K3s
Soberanía con gestión ligera
▶ K3s: Kubernetes certificado en un solo binario
▶ Rancher gestiona múltiples clusters on-premise
▶ Ideal para edge computing y recursos limitados
▶ Menor overhead que OpenShift, control total
TIER 3 Kubernetes Self-Managed
Soberanía manual, máxima flexibilidad
▶ Control absoluto del cluster y la red
▶ Helm charts + operators propios
▶ Requiere equipo DevOps dedicado
▶ Complejidad de mantenimiento alta
TIER 4 Nube Pública (AWS / GCP / Azure)
Sin soberanía por diseño inherente
▶ Datos transitan y residen en infraestructura ajena
▶ Sujeto a legislación extranjera (CLOUD Act, FISA)
▶ Vendor lock-in en servicios managed (Bedrock, Vertex)
▶ Costos recurrentes proporcionales al volumen
En el contexto de este proyecto: La ley chilena de protección de datos personales (Ley 21.719) exige que el tratamiento de datos personales respete la finalidad y seguridad. Usar nube pública para correos personales implica cesión de datos a terceros, lo que contradice el principio de soberanía que fundamenta esta arquitectura.
